### 一个流水线 bug 及修法
晚命中的模型会跑满 R0-R4 阶梯、且 R4 直接被喂答案，于是靠"复述喂的答案"攒钩子，钩子数虚高、不跨轮次可比。

修法：**钩子只数 R4（喂答案那轮）之前模型自达的**。已应用于全量 API 重判。

## 关键发现

1. **fable 两个模态都第一**，chat模式大幅领先，体感和其他LLM**不是同一物种**。
2. **gpt55 是 web-vs-API 差异最大的**：chat 59→ API 201。一部分原因是用户 chat 提问方法不标准。
3. **opus 行为分较低**，容易过度谨慎导致翻供，或聪明反被聪明误的过度解读。
4. **hy3 两模态都垫底**，chat 错误洗白、API 反复翻供。

## 注意 / 待核

- **chat 提问不可控**：gpt55 chat 低分部分是"作者提问先给了答案"导致的自达失分，非纯能力，实际聊天体感很好。API 的对话更干净可控。
- **fable API 的"林夏主动"**：按作者规则（严谨悬置不罚）取"正确"。
- **评分 agent 可能不如被测模型**：阅卷 agent 的水平未必高过答题 AI，这是误判的一个来源。本项目如实承认，暂时没有很好的办法规避；欢迎读者换不同的 agent 当阅卷人重打分，结果或许不同。
