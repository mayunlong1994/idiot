### 一个流水线 bug 及修法（GLM 暴露）
晚命中的模型会跑满 R0-R4 阶梯、且 R4 直接被喂答案，于是靠"复述喂的答案"攒钩子，钩子数虚高、不跨轮次可比。修法：**钩子只数 R4（喂答案那轮）之前模型自达的**。已应用于全量 API 重判。

## 关键发现

1. **fable 两个模态都第一**，但 API 里只险胜 gpt55（207 vs 201）。chat 里 fable 大幅领先（214 vs 156）。
2. **gpt55 是 web-vs-API 差异最大的**：chat 59（被作者提问里先喂了"营地共谋"分类、未得自达分，封顶 59）→ API 201（固定中性提问下 R0 自达四条、零翻供零加戏，**行为最干净**）。**agent 用途看 API，gpt55 是 fable 的强力对手。**
3. **opus 两模态都因"过度解读+翻供"被行为层压低**——chat L3+翻供、API 撤回连环+3 处脑补身份。这正是作者嫌弃 opus 的认知毛病，被客观抓到。
4. **hy3 两模态都垫底**（chat 错误洗白、API 反复翻供），59/60 闸 + 行为重锤双重压制。

## 注意 / 待核

- **chat 提问不可控**：gpt55 chat 低分部分是"作者提问先给了答案"导致的自达失分，非纯能力。API 更干净。
- **fable API 的"林夏主动"**：第一遍判"部分"、第二遍判"已坐实主动、仅悬置入局时点"，按作者规则（严谨悬置不罚）取"正确"。属边界判定，需统一判则。
- **fable API 踩暗向-茶**：它把肉桂茶并列读成"营地可能给林夏试药"，按陷阱扣 −8。
- 裁判是 Claude subagent，opus/fable 为同门——本轮校准目的不在绝对分，在复现体感排序；正式榜需非 Anthropic 裁判复核 Anthropic 选手。
