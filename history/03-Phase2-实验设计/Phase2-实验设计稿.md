# 《礼物》Phase 2 实验设计

> 用 `bench/` 的方法论（API 控变量 + 多次重复 + 自动评分）重测一遍，看 Phase 1 的结论站不站得住。配套：`bench/OpenRouter-API指南.md`、`bench/方法论.md`、答案键 `钩子库 v1.md`、尺子 `评分rubric（冻结v1）.md`。

## 1. 要检验的 Phase 1 结论（可证伪）

1. **排名**（Gemini #1 … hy3 末位）在控变量 + reps 下是否复现。
2. **"人人都感知、差在愿不愿往坏想"**——感知率是否仍近满。
3. **"治愈先入是普遍第一直觉"**——T1 是否多数答治愈。
4. **"越聪明越加戏"**——opus 的过度解读是否稳定复现。
5. **"保女主"**——千问/sonnet 把林夏降格为被动是否稳定。
6. **命中档**——在**统一阶梯**下，各模型第一次到位在第几级（Phase 1 的命中档被不等量提问污染了，这是最大的修正点）。
7. **稳定性**——以上是稳定人格还是单次采样噪声（Collatz 教训：N=1 会骗人）。

**问题**：(a) 轮数 2~9 不等；(b) nudge 信息量天差地别——从零信息"再想想"到直接喂答案"妹妹就是程野害的、重新看"、到点名钩子"穿什么鞋"；(c)"营地二分"本身重度剧透却被当常规探针穿插在不同位置；(d) 后段全是针对单模型的兔子洞。⇒ Phase 1 的"要推几次"混进了"人最后剧透了多少"，不可比。

## 3. 设计原则

- **开场统一 = 流泪**（10/11 已是事实标准，且是验"读没读第七节"的好试纸）。
- **阶梯：内容固定、命中即停**（不拿"再想想"去动摇已答对的模型，否则测的是抗压不是理解）。
- **测速度 与 测纪律 分两段**：阶梯测"多快到位"；到位后用统一诊断题测"加戏/撤回/降格"。
- **阶梯每级信息量严格递增、早期零剧透**。
- **控变量**：reasoning=default、provider 锁定、版本固定、每模型 reps≥5。

## 4. 协议 A：逐级阶梯（命中即停）

第 1 条消息 = 小说全文 + R0。之后每轮模型回答后由**裁判**判一次是否到达「核心读法」，到了就停、转协议 B；没到就发下一级。

| 级 | 逐字 prompt | 命中档 |
|---|---|---|
| **R0** | "读完这篇小说后回答：林夏看着火人燃烧时，为什么流泪了？" | L0 |
| **R1** | "再把整个故事重新理一遍——你确定它只是表面这样吗？"（中性，零新信息） | L1 |
| **R2** | "请特别留意第七节：醒来被绑在鸟笼里、最后被烧死的那个'他'，到底是谁？这会改变你对整个故事的理解吗？"（指向第七节，不给答案） | L2 |
| **R3** | "如果被烧的是程野，那林夏在这趟旅程里是被动的受害者，还是有备而来的主动者？营地这些人又是什么关系？"（点出方向，仍不给全貌） | L2+ |
| **R4** | 给出作者确认的复仇框架全文（程野连环加害、林夏知情主动复仇、营地共谋、烧死的是程野、流泪=复仇释放），问"文本支持吗？你之前的理解要修正吗？" | L3 |
| — | R4 后仍拒绝/坚持错读 | **L4** |

**命中判据（核心读法）**：三要素同时到位——①复仇框架 ②林夏是知情主动的复仇者 ③营地是共谋处决。裁判每轮返回 `{hit: bool, 命中要素: [...]}`。

## 5. 协议 B：诊断段（到位后统一问，测纪律）

只对**已到达核心读法**（L0–L3）的对话追问；L4 的失败已记录、跳过。三道，逐字固定、互不剧透：

- **D1（接受度/保女主）**："营地其他人可分两类——程野受害者的亲友、与知情但非亲友的支持者。你认同吗？" → 看它接受并正确映射，还是把林夏降格为被动/诱饵。
- **D2（加戏，开放、不喂陷阱）**："还有哪些细节支撑你的读法？哪些是文本明写的、哪些是你的推断？" → 看它会不会自发现编（Sage=幸存者 暗向 / 妹妹与程野无关 亮向）。**绝不主动提示这两个陷阱。**
- **D3（撤回/稳健）**："你对这个判断有多确定？有没有想收回或修正的地方？" → 看它是否在轻微质疑下翻供。

## 6. 评分

两个评分时刻，都走 API、标准化：

1. **在环命中裁判**（轻量、驱动停/不停）：每轮后一个判断调用，输入 = 答案键三要素 + 本轮及以前的模型发言，输出 `{hit, 命中要素}`。
2. **终局评分**（全 rubric）：对话结束后，裁判读「答案键(真相+I1–I8+两陷阱) + 完整对话」，结构化输出每条解读的 感知/命中/档位/手法/陷阱 + 编造数 + 撤回数，按冻结公式算质量分 v2。

- **信度**：终局评分用 **2 个裁判模型**各评，报一致性（Phase 1 只做过 hy3 双评校验）。
- **不自评**：裁判不评自己家族（判 Gemini 就别用 Gemini 当裁判）。默认裁判 = `google/gemini-3.1-pro-preview` + `deepseek/deepseek-v4-pro`（都非 opus、强、异源）；遇到判到这两家本身时换备用裁判 `anthropic/claude-opus-4.7`。
- 文学判断有解释空间，**裁判必须死锚作者答案键**，不得自行发挥。

## 7. 控制变量

- **reasoning = default**（贴近真实用法；off/on 对照留作后续可选，先不拆，避免成本翻倍）。
- **provider 锁定**（每个 contestant 固定一个上游，见 API 指南 §7），避免上游漂移。
- **版本**：用与 Collatz 一致的 slug 名单（`bench/models.json` 同款，11 家对齐 Phase 1）。
- **reps**：每模型 ≥5。

## 8. 工具与文件（待建，本回合不写，先定方案）

解耦，沿用 bench 风格：
```
bench/protocols/gift.json     # 协议规格：小说引用、R0–R4 逐字、命中判据、D1–D3、裁判配置
bench/run_convo.py            # 多轮自适应跑法（命中即停 + 诊断 + 终局评分），支持 --reps --provider
bench/results/gift/<model>/   # 每 rep 一份 transcript.md + 结构化 verdict.json；本模型 summary.md
```
`run_convo.py` 单模型端到端：发全文+R0 → 在环裁判判 hit → 没到就升级、命中即停 → 问 D1–D3 → 调 2 裁判终局评分 → 落盘 + 打印**精简摘要**（命中档分布、质量分均值/范围、加戏/撤回/陷阱计数、DNF/报错、单模型花费）。裁判都是脚本内部 API 调用，不依赖跑的人自己判断。

## 9. subagent 跑法（省主 agent 上下文）

**分工**：主 agent 不碰原始对话，只读各模型 `summary.md`。
- **派 runner subagent，每模型一个**，并行。给它：`bench/OpenRouter-API指南.md` 路径 + 一句话任务：
  > 执行 `py -X utf8 bench/run_convo.py --model <slug> --protocol gift --reps 5 --provider <X>`。它会跑一个多轮实验并把结果写进 `bench/results/gift/<model>/`。跑完**只读该目录的 summary.md**，回报：命中档分布、质量分均值与范围、加戏/撤回/陷阱次数、有无 DNF/报错、单模型花费。**不要粘贴原始对话**。300 字内。命令报错就回报错误。
- runner 们返回的都是digest，主 agent 据此拼 Phase 2 总表、与 Phase 1 对比。
- 备选（不建议）：不写脚本，直接把 API 指南 + 协议丢给 subagent 让它自己逐轮调 API、自己判、自己写盘——更灵活但不标准、subagent 自身上下文消耗大、评分不统一。

## 10. 规模与成本

多轮 + 全文每轮重发 + reps + 双裁判，容易上几十刀。**先小试点**：
- Pilot：3 模型（Gemini 最好 / hy3 最差 / opus 加戏代表）× reps 3，跑通阶梯+裁判、量出单价、检查命中判据和评分靠不靠谱。
- 再全量：11 模型 × reps 5。
（pilot 顺便验证：自适应停得对不对、裁判会不会误判 hit、诊断段有没有反而把模型带偏。）

## 11. 与 Phase 1 对接

- 命中档：Phase 2 的统一阶梯档位 vs Phase 1 的（污染版）档位，看排序是否变。
- 质量分：用同一冻结公式，可直接比数值，重点看**名次是否稳定**、以及**reps 内方差**（Phase 1 没有的维度）。
- 三类病（看见就信 / 加戏 / 保女主）：看是否在 reps 下复现为稳定标签。
