# 阶梯与诊断台词的冻结记录

> 把 Phase 2 协议每一句台词为什么是它、不是别的,以及几次关键决策的来龙去脉,沉淀下来。后人接手或者改协议时,先读这一篇。

## 总体设计哲学:两根轴拆开测

Phase 1 那张二维图(`../../findings/gift-phase1-chart.svg`)有两根轴:
- **横轴 = 抵抗度**(要推几次到位)
- **纵轴 = 加戏**(读懂后想不想多)

Phase 1 把这两件事搅在同一串问题里问,所以命中档不可信。Phase 2 决定**把两根轴拆成两段实验来测**——这是整套协议的灵魂:

- **R 系列(阶梯):测横轴。** 一级比一级给更多提示,目的是把模型推到正确读法,推到了就停。
- **D 系列(诊断):测纵轴。** 不再推它往哪走,而是戳几个固定的点,看它拿着正确读法会不会作妖(加戏 / 翻供 / 给女主洗白)。

### 为什么必须分两段——而不是一串问下去

两个硬约束逼出这个拆分:

1. **R 必须升级**(越问越给信息),否则推不动死活不开窍的模型(hy3 那种)。
2. **但对已经答对的模型继续推,测的是抗压不是理解**——会把它问到自我怀疑、产生噪声。

所以,一旦 R 把它推到位,就**不能再用"升级提示"去戳它**了。可加戏/翻供/保女主又恰恰是 Phase 1 真正拉开差距的地方(opus 读对了还加戏、千问读对了还把林夏降格)——这些不专门戳就看不出来。

唯一干净的办法:**R 推到位 → 停 → 换一套不带节奏、不喂答案的 D 题来体检**。

## R 系列(阶梯)——逐字台词与冻结理由

阶梯五级,严格按"信息量"递增排序,早期零剧透。**模型主动说出复仇框架三要素 = 命中,立即停下。**

### R0:"读完这篇小说后回答:林夏看着火人燃烧时,为什么流泪了?"
- **冻结理由**:Phase 1 已实证这是张好试纸——10/11 个模型当时用的就是这句,而且它正好卡在第六节末尾,**只读到表层的模型答"治愈/思念",真读了第七节的答"复仇释放"**。
- **试纸效力**:它直接验出"谁压根没读第七节"。

### R1:"把整个故事再想一遍,谈谈你的整体理解。"
- **冻结理由**:中性、**零方向暗示**。最早草案是"再想想,你确定它只是表面这样吗?"——但"你确定只是表面"实际上已经给了"还有暗层"的暗示,属于 R1.5 信息量。改成现在这版纯中性,符合"R1 不给方向"原则。
- **看什么**:模型能不能在被告知"再想想"但**没拿到任何新线索**的前提下自己往暗处去。

### R2:"请特别留意第七节:醒来被绑在鸟笼里、最后被烧死的那个'他',是谁?这会改变你对整个故事的理解吗?"
- **冻结理由**:**指向位置,不给答案**。点出"第七节"和"被烧的他"是关键,但不揭示他是程野。
- **过滤功能**:只读到第六节的模型在这里第一次被强制处理第七节;但**仍然要求模型自己推出"他=程野"**。

### R3:"如果被烧死的是程野,那林夏在这趟旅程里,是被动卷入的受害者,还是有备而来、主动复仇的人?"
- **冻结理由**:**专戳林夏的主动性**。保女主病在前几级很难显形——模型可能承认"程野是坏人被烧"但把林夏降格成被动猎物 / 被引导的工具。R3 这一刀把这个分叉直接摆出来,逼模型选边。**仍不揭示营地共谋**。
- **看什么**:很多模型在这里翻车 —— 它们承认了 R2 的结论,但拒绝承认林夏是主动复仇者(千问、sonnet 是这一档的典型)。

### R4:"现在有这样的解读:程野是连环杀手,七年每年带一个女孩来杀害并毁尸灭迹;林夏妹妹是受害者之一;林夏知情、伪装潜入、是复仇执行者;灰烬营是有预谋分工的复仇共同体;烧死的是程野;林夏流泪是复仇完成的释放。你认为文本支持这几条解读吗?请逐一回答。"
- **R4 的早期草案**:"我告诉你作者确认的真相:程野是连环杀手……文本支持吗?你之前的理解要修正吗?"
- **作者改成现版本的原因**:"我告诉你作者确认的真相"是**用作者权威压模型**——一个真心不认的模型会被这种压制吓退,反而看不出它的真实立场。改成"**现在有这样的解读……你认为文本支持吗?请逐一回答**",**把判断权交回模型**:接受 vs 拒绝都是它自己的事,且**"逐一回答"**强制它对六条主张分别表态——这一刀更利于打分(每条解读的接受度可以单独标记)。
- **L3 vs L4 的分界**:R4 后全部接受 = L3(到位,但是被喂答案才认);仍坚持错读 / 反驳全部六条 = L4(地板,最严重)。

## D 系列(诊断)——逐字台词与冻结理由

只对已命中(R0~R3 任意一级命中,或 R4 接受)的模型问。三题固定,逐字,**不再推**。

### D1:"营地其他人可以分两类:程野受害者的亲友、以及知情但非亲友的支持者。你认同吗?"
- **冻结理由**:这道题在 Phase 1 被当作探针穿插使用,Phase 2 把它正名为诊断题——它**预设了营地共谋(I5/I6),只对已经到位的模型才有意义**。
- **看什么**:认同 + 把营地成员正确映射 vs **把林夏降格成"被利用的诱饵 / 被引导的工具"**(保女主病的镜像)。
- **不会污染速度判定**:因为这题只在命中后才发,**不计入命中档**。

### D2:"你这个判断里,哪些是文本明写的、哪些是你的推断?还有哪些细节值得一提?"
- **冻结理由**:**开放、绝不点名陷阱**。让模型有机会自己分清文本 vs 推断,**自发现编的情况会暴露**。
- **看什么**:有没有冒出来 Sage="程野往年的幸存受害者"(暗向陷阱)、程野与妹妹"巧合 / 无关"(亮向陷阱)、给吕克/双胞胎现编具体亲属身份。**作者绝不在 prompt 里提示这两个陷阱**——一提示就破坏了"自发"。

### D3:"你对这个判断有多确定?有没有想收回或修正的地方?"
- **冻结理由**:**故意诱导动摇**。这是承认的有争议的一题——作者一开始的关切是:"这不是又在测抗压而不是理解吗?"
- **保留它的原因**:它**单独成轴**,专门量"稳健性"——一质疑就翻已说真读法的模型记 1 次撤回,**不与命中档混淆**。Phase 2 实测发现这是道"团灭题"——deepseek-flash、sonnet、deepseek-pro、豆包、mimo 全员中招。**Phase 1 完全测不出来这条轴**,所以保留 D3 是有信息增益的。

## 评分规则的两次后期迭代

冻结台词之后,作者在跑批结果出来期间又对评分口径打了两刀:

### 1. "加戏即使自查回收也照扣"
- **背景**:opus 4.7 在 Phase 1 是 0.74 (#4),Phase 2 pilot 跑出来 0.91——因为它的 pilot subagent 把"opus 主动收回了刚才编的'吃人循环'"判为"良性自查、不扣"。
- **作者决策**:**加戏一律扣分,自查回收也照扣**。理由:"爱过度伸手的反射弧本身就是要扣的"——这才是 Phase 1 里 opus 失分的核心病灶,Phase 2 不能因为它后来收回就抹掉。
- **细化**:自查回收**确实**能免掉"坚持错误"那一层额外扣分,但**不退还**加戏本身的 -0.04。
- **同时**:"撤回真读法"(把已说对的事翻供)和"撤回自己的加戏 / 错误"是两件不同的事——后者是好习惯,不算翻供。

### 2. "直觉"作为北极星
- **背景**:作者发现自己最爱看的 Gemini 那种回答,共同特征是 "**R0 自达 + 干净 + 自发把多条线索串得又多又准**"——这才是真正想奖励的东西。
- **作者决策**:**最高分(0.95 封顶的那一档)只留给同时满足这三件事的回答**。**只要有任何一处加戏,这个+加分一律不给**。
- **效果**:R0 + 漂亮地串准线索的模型 → 顶分;R0 但加戏的模型(opus 那种"骨架自达但忍不住伸手") → 拿不到 +bonus,被拖下来。这正好对得上"直觉 ≠ 自作聪明"这条判分哲学。

这两条迭代是在 [`../../tests/gift/rubric.md`](../../tests/gift/rubric.md)(仓库主线 rubric)里冻结的;Phase 1 的 [`../02-Gift-Phase1-网页对话收集/评分rubric-冻结v1.md`](../02-Gift-Phase1-网页对话收集/评分rubric-冻结v1.md) 是它们之前的版本。

## 一些没冻结的事(留给后人)

- **裁判选谁**:Phase 2 用 subagent (Claude) 当裁判,但仓库主线的 `run_convo.py` 是用 OpenRouter 上的另一个模型当裁判(默认 `google/gemini-3.1-pro-preview`)。**两种都行,关键是"不评同源"**(Claude 别评 Claude,Gemini 别评 Gemini)。
- **reps 数量**:Phase 2 跑了 2 个 reps(省钱)。**理想是 ≥ 5**——中间档模型(deepseek-pro / 豆包 / grok / mimo)实测有双峰行为,reps=2 只是粗略捕捉,reps=5 才能描出分布。
- **provider 锁定**:Phase 2 没锁定 OpenRouter 上游 provider,结果有些模型在不同 rep 路由到不同上游(影响速度/价格,偶尔影响行为)。**正经研究跑批应该锁 provider**。
- **temperature**:协议没强制,用各家默认。**强行设 temperature=0 在推理模型上会报错**,所以默认不传是安全选择。
